# 捷径自由选路计圈修复

问题：第二条捷径的低处水道与主路中途相交。玩家先走主路、再从交叉口进入捷径后半段时，没有经过高架捷径入口，旧计圈逻辑不接受后半段的捷径检查点。两条路线的同编号检查点位置也不同，因此合法换路仍可能漏点。

改动：将两条捷径各自从分岔到汇合的区间设为自由选路区。原 CP12–14、CP16–20 只作内部赛程进度参考，不再作为必经点；HUD 直接指向汇合后的公共 CP15、CP21。顺向穿过下一个公共检查点时补齐该区间逻辑进度，保留每圈 24 段的现有计圈、训练记录和排名数据格式。未经过自由区前的公共必经点，不能跨段获得进度。起终点、逆行、离开水道、错误高度和瞬移校验保留。必经点表只在创建比赛时计算一次；驾驶、碰撞、跳跃和渲染模块未改动。

验证：

- `tests/shortcut-choice.test.ts` 覆盖第一条捷径走或不走，以及第二条捷径入口/中途分别选主路或支路，共 8 种组合，各跑三圈；另测公共点缺失、逆向、离水、瞬移、错误高度及重复穿越不能计圈。
- `browser.json` 使用修复前冻结构建与修复后生产编译的 Game.frame 对照。旧版按“主路进入、交叉口转入捷径后半段”实际驾驶，驶出汇合区后仍停在已过 18、等待 CP19。修复后该路线连续三圈正常结算；第二岔口其他三种组合也分别完成三圈。保留四名实体 AI 和完整物理规则；不注入玩家检查点或传送玩家。为了稳定转弯，测试驾驶员在交叉口减速；加速功能模拟期间跳过 GPU 绘制，截图时恢复，模拟耗时不用来声明帧率。
- 192 项自动测试、TypeScript 检查及生产构建通过。完整三圈 AI 时间仍为约 4:30、5:04、5:19、5:42。
- `performance.json` / `performance-summary.json` 为独立实际渲染对照：同一 Edge、1600×1000、DPR1、标准画质，A/B/B/A，60 帧预热、240 帧测量。城市五艇 36.77 → 36.80 FPS；第二捷径五艇 35.26 → 35.24 FPS，两处波动均小于 0.1%。绘制调用、三角形、分辨率、水面细分、法线纹理和最终物理位置逐项一致，未降低画质。

# 立体赛道前置设计与自查（V1）

此文档与[带高度俯视规划图](plan.svg)在赛道实现修改前创建。保护点：`vertical-track-baseline`。不重建城市，不改玩家加减速、转向曲线及资产。

主线沿用4745米平面闭环，24个检查点、三圈。起点及现有高质量样板区保持0米，普通静水仍水平；升降仅发生在有底板、侧壁、支撑的人工输水槽。

共六处：两普通跳台、一中型跳台、两自然起跳点、一高架捷径长跳。主线有五处，选择S2会替代主线D2，不是每圈强制经过六处。高差之间保留长距离平缓竞速。

## 公平性与技术约束

- S1约节省100m，S2原平面路径约节省66m；窄道、弯道、14m落差及汇流风险抵消收益，不给分支额外速度。S1可小幅弯曲调整，长度收益以实现后测量为准。
- 分支必须从合法入口激活；顺序通过与主线对应的分支检查点后才能合流，不能从中段横切刷圈。检查点检测包含实际高度。计分进度仍用经过的检查点及当前扇区，防止捷径路径长度导致虚假领先。
- 承托面、腾空、落地采用共享模块：传统跳台仍用船体支撑比例与扫掠；自然起飞依据实际面高、坡度和速度。没有离水承托时不能按时间强制回零。
- 碰撞保持已有胶囊体和水平响应，用世界高度区分上下层；同高度的空中艇仍然碰撞。
- 摄像机仅适配高架地面基准，保留原跟随/FOV响应；尾浪、水花及音频需认识高架水面接触，不能误当全程飞行。
- AI保持现有速度规则，获得前方三维承托与分支信息；窄分支居中、提前对准，落地不瞬移回路线。
- 重置落在最后已验证检查点对应的安全分支或主线承托面，跳台边缘和落差唇口不作为恢复点。成绩使用新赛道版本独立记录，避免旧平面赛道成绩混入。

## 布局自查结论

平面闭环和城市主布局不变。A区爬升开始于29%旧桥之后；D1预计在38.4%之前落地，避开40%旧桥；J2在该桥之后。B区和S2没有穿越已知低桥。新增支撑应落在水道边界外；隧道与S2出口保留净空和合流缓冲。规划在速度40–60m/s下为D1预留约80–120m落地区；实现后必须用真实物理与浏览器再检验，图示不是已通过测试的证明。

规划自查通过，可以按本图进入代码阶段。若模拟发现曲率、净空或落点不合理，应修正并在验收文档记录，不隐藏与规划的差异。

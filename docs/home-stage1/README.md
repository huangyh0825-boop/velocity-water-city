# 首页、单人训练与真实房间大厅

本阶段按用户确认完成大厅，不实现联网竞速，也不把 AI 包装成其他玩家。

结构：`src/app/GameApplication.ts` 管理首页和训练生命周期；`src/gameplay/RaceSession.ts` / `PlayerCommand.ts` 定义会话和操作端口；`LocalRaceSession.ts` 从 Game 提取固定 60 Hz 驾驶、碰撞、跳跃、氮气、检查点和计圈规则；Game 继续负责原有渲染与声音。该规则模块可以在无 DOM、无 WebGL 环境中执行。

训练支持输入任意可安全计数的正整数圈数，结束判定、HUD、倒计时和成绩均使用实际选定圈数。难度分简单和困难，最快 AI 通过完整赛道实测分别约 2 分钟和 1 分 30 秒一圈。AI 使用正常驾驶、碰撞、跳跃和氮气，不注入完赛时间。玩家驾驶参数和画质保持原值。

设备档案首次要求取游戏 ID，之后自动恢复，支持改名。保存设置、开始/完成次数、累计完成圈数、驾驶时长和最近 30 次训练；成绩按圈数和难度区分。后台或关闭页面时保存未完成记录，继续到完赛时更新同一条记录，避免重复计时。

大厅为独立 Node.js 服务，真实管理四位房间号、成员和准备状态；同一房间最多五人。`lobby-browser.json` 验证两个独立浏览器会话通过本机与局域网入口同号加入、互见、准备、改名、刷新不重复、掉线重连及房主转移。主页和大厅阶段没有请求 Game 模块或任何 3D 模型，手机无横向溢出，正式页面没有测试全局变量。

`training-browser.json` 从真实首页选简单 1 圈、困难 2 圈，完整运行应用与 Game.frame，分别经过全部 24、48 个检查点并结算，返回首页及刷新后保留档案与记录；困难两圈均故意在 S2 飞跃偏航后恢复，覆盖 CP19 修复。另选 37 圈后中途刷新，验证未完成记录保存。GPU 仅在加速功能模拟期间跳过，截图时恢复；功能测试执行耗时不用于声明帧率。

运行与部署见 `server/README.md`。当前已准备可独立部署的大厅服务器和配置入口；公网需要部署该服务器并配置前端地址，不能仅上传 GitHub Pages 就宣称公网大厅可用。

帧率对照见 `performance.json`：同一 Edge、1600×1000、DPR1、标准画质、A/B/B/A 顺序。城市五艇平均 37.84 → 37.93 FPS；第二捷径五艇 36.36 → 36.25 FPS，波动约 ±0.3%，未见明显回退。绘制调用、三角形数与终点物理位置均一致；CPU 单帧均值分别由 21.21 → 20.82 ms、24.46 → 23.74 ms。没有改模型、纹理、水面、阴影或画质参数。

189 项自动测试与 TypeScript 检查通过，游戏生产构建和独立大厅服务构建通过。首页和房间使用正式生产页面验收；训练完整流程使用独立测试入口，正常发布页面不包含测试控制器。

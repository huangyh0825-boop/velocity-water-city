## 美术实现与数量口径

保留原样板195处模块实例、三栋原地标及其设施。新增1699处常规模块实例，现有全图常规模块共1894处；另外在五个新区各放置两处**原精度样板地标**，新增10处，中央样板三栋未移动。常规模块数量不包含这些地标和样板GLB内部的小设施。

复用26类常规建筑和三类精修地标，共29类建筑形态。常规模块与样板使用相同GLB、同一套PBR纹理和玻璃视差室内着色器；地标从原Blender集合提取完整网格、倒角、窗框、楼层板、入口、屋顶及材质，没有低精度替代。清除59处旧简化建筑及旧的100个方块远景占位，使用新的完整城区与连续天际线替换。

## 性能实现与测量边界

沿用原样板的按材质BatchedMesh/实例化体系，建筑几何与材质共享；新增工程设施和商业屏也按材质批量绘制。保持原近中远距离等级及滞回，新补远景建筑一旦靠近另一段赛道，会使用近/中档网格，避免低精度轮廓出现在玩家面前。布局碰撞使用空间网格，启动生成约一秒量级，不在驾驶帧重复生成建筑。

未降低玩家、AI、贴图、水面或内部渲染分辨率；未缩短相机视距，也未用距离隐藏本来可见的建筑。现有103个模型/贴图文件逐文件核验未修改。

正式对照：[performance-controlled.json](performance-controlled.json)。同一Edge进程、单一页面；先测旧版并销毁其渲染器及WebGL上下文，再测新版。1600×1000、DPR1、标准画质、五艘同精度快艇、水面时间t=12；每区compileAsync后120帧预热、120帧采样，保留全部帧与1% Low，不丢弃异常值。

**测试时显卡存在其他3D客户端负载。** Windows计数器在一次测试期观察到其他客户端约47.93%、QA Edge约33.13%的3D引擎时间；QA结束后的另一次样本仍有客户端71.64%占用，见[gpu-load.json](gpu-load.json)。这不证明每一帧负载恒定，也不能据此校正FPS。GPU计时包含共享调度影响，不能把其全部耗时归因于城市。中间存在并行QA的测量不用于最终结论；双上下文压力测试也不作为正常单实例帧率。

该有负载对照中，新版各区约17.1–18.8FPS，旧版约16.4–20.0FPS；部分区下降，不能宣称性能完全无退化。地标补齐前的另一次单区分通道暖机诊断曾约59.3FPS，见diagnostics目录；它既不代表最终版帧率，也不能与有负载旧版跨轮比较。**独占GPU、长时间驾驶及稳定60FPS尚未验收**，需要在显卡负载可控时复测，不擅自关闭用户其他应用。

## 实际验证

- TypeScript `tsc --noEmit`通过；生产Vite构建通过，仅保留原有大chunk提示。
- **136/136自动化测试通过**，含原驾驶、碰撞、跳跃、AI、氮气、特技、检查点，以及新增全图资产、净空、室内分布、路牌和GLB边界测试，见[完整输出](tests.txt)。
- 私有生产编译入口使用真实`Game.frame`、60Hz物理、正常碰撞与自动转向/刹车输入：玩家与四名AI均通过72个检查点并完成三圈；玩家第二圈走S1、第三圈走S2，见[实跑记录](after/full-drive.json)及[结算截图](after/race-result.png)。为了等四名AI全部完赛，QA让玩家停在最后检查点前等待，不改生产比赛规则。加速QA每12个物理步绘制一次，不能据此推算正常游戏FPS。
- 自动输入有157个边界接触步骤，未卡死或通过修改驾驶物理绕过；这不是人类手动全程无碰撞驾驶验收。
- 4450个玩家/AI实际采样姿态对2071组建筑与工程包围范围审计未发现侵入，完整路线另有连续3D净空测试，见[path-audit.json](path-audit.json)。建筑是独立视觉资源，没有关闭艇碰撞掩盖遮挡。
- 普通生产入口实际W加速到37km/h、A转向、S降至0、重新比赛、氮气恢复40%；42个模型/贴图请求均200、无浏览器错误、普通入口无QA全局钩子，见[生产检查](production-results.json)。
- 全主线48个位置、两条捷径、高架区、六区近景与地标均有真实浏览器截图。图集全部图片可解码。原样板与新区的相同条件对照供用户逐张审查，不仅展示精选景点。

## 当前限制与验收重点

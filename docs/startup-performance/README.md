## 已完成的改动

- **无损资源传输**：两份高质量模型由 173.8 MB 原始 GLB 改为 49.4 MB 的 meshopt + gzip 资源；在 Worker 解压 gzip，再在后台线程解码 meshopt。所有顶点、索引顺序、法线、UV、权重、骨骼、挂点、动画及材质值逐字节/逐项校验一致。没有简化、量化或重排网格。
- **无损贴图与共享**：37 个 PNG 引用归并到 31 张 WebP；唯一原始 PNG 约 110.0 MB，WebP 约 56.5 MB。每张解码 RGBA 和原图完全一致，保留原分辨率及 ICC。原始模型与 PNG 保留，发布时只复制实际运行依赖。
- **启动响应**：缓存相同赛道网格的候选线段，并提前排除确定不含水道的地块。保留原搜索顺序、最近点、交叉路口和远处路线回退规则；新增 4,800 组投影字段精确对照及沿线边界测试。加载器先绘制；贴图上传分批让出主线程；HDR 反射目标的 Shader 在绘制前异步预热。
- **行驶计算**：按坐标及有效路线缓存投影结果；外部修改返回对象不会污染缓存。复用骑姿的世界旋转，避免相同关节祖先矩阵反复更新；室内可见集合未变时不重传矩阵；已自行剔除的实例不再计算未使用的包围球。
- **渲染计算**：骨骼权重严格等于零时省略对应骨骼纹理读取，保留所有非零影响；选手自阴影坐标复用已有世界坐标。保留标准画质的 2048² 阴影、1024² 水面反射、抗锯齿、像素比策略、所有原有模型面数与远景。

## 帧率波动与限制

冻结五艇的静态机位测试没有稳定的大幅收益。先前多轮优化版 city-driver 约 48–49 FPS、远景约 37 FPS、高架约 65–66 FPS、隧道约 41–42 FPS；最后一轮测量出现以下整体下降，保留全部原始结果，不把它们隐藏或当成已解决：

|机位|首轮旧版 FPS|最后一轮新版 FPS|
|---|---:|---:|
|city-driver|49.5|19.9|
|city-distance|36.4|15.4|
|elevated-five|64.2|26.6|
|tunnel-five|41.0|17.0|

同机位 Draw Calls 与所有 Pass 的三角形数完全相同。随后专门在当前条件下复查 city-driver：旧版 **20.03 FPS**，新版 **19.97 FPS**，同时启动耗时旧版 **36.23 秒**、新版 **10.81 秒**（before-late.json / after-late.json）。这次低帧率并非新版独有；尚不能确定共同波动的具体原因，也不能用较早的好结果承诺稳定帧率。五艇本身约 2,464 万模型三角形，在主画面、反射和阴影重复绘制，GPU 几何负担仍很大。手机仅进行了浏览器触控模拟，未获得真机长期帧率与温度数据。

## 复现与文件

正常运行及构建直接使用已生成的压缩资源。重新导出美术资源后，先运行 `python scripts/pack-runtime-textures.py`（Pillow），再运行 `npm run assets:pack`。`npm test` 会核对压缩模型与原始模型的一致性。`npm run build` 自动收集资源依赖，不复制历史贴图与原始大模型进入发布包。

主要证据：before.json、release.json、gameplay-forward.json、gameplay-reverse.json、visual-diff.json、lossless-models.json、lossless-textures.json、production.json。所有记录在 `C:\快艇\docs\startup-performance`；探索版 trial/after/final/verified 也保留。工具为项目已有 Playwright QA，基线通过 Git 源码覆盖构建，未回退用户工作区。

实现参考：[meshoptimizer 官方文档](https://github.com/zeux/meshoptimizer/blob/master/gltf/README.md)、本地 Three.js GLTFLoader 与 WebGLRenderer 实现。

## 已确认的问题一：不是最终合流夹角大，而是出口前先折回

对现有`CityTrack.makeShortcut()`的实际129个采样点测量：最终汇入主线的夹角约 **12.9°**，表面看已经低于30°。但S1自身约88%—92%处存在小尺度回折，局部方向变化最高约 **160°**，离散曲率估算半径最低约 **1.03m**。

原因是先生成Catmull-Rom曲线，再沿不断旋转的局部侧向叠加`−40*sin(πq)`偏移。偏移与基曲线的曲率在出口叠加，最终采样路径出现回折，不能仅凭基曲线平滑或最终切线正确判断可驾驶性。[测量数据](current-metrics.json)与[旧出口截图](current-shortcut-exit.png)保留原状。

### S1推荐方案

- 入口仍在主线48%，出口由60%向后延至 **61%**，增加约48m主线方向的合流余量；不改主线平面控制点。
- 取消事后正弦侧移，改用明确端点切向约束的样条。图中候选为三次Bezier，入端控制柄80m、出端240m；长约480.6m，对应主线621.1m，节省约140.6m。
- 候选曲线全程最小半径约77.4m，末端切线与主线一致，没有旧版回折。这是几何采样结果，**不是已经通过高速驾驶验证**。
- 实施时末端补曲率连续过渡，最终80—100m逐步从全宽14m放宽至24m，主线合流局部从30m放宽至40m，缓慢恢复原宽；边界同步重建，不能留下护栏尖角。
- 弯中预计合理速度140—160km/h，允许氮气接近后提前减速；不要求180/216km/h无条件全油门转过。必须用现有惯性和转向实际测试后才定稿。
- 窄隧道和入弯控制保留风险，不用不合理折返制造难度。出口门架、内墙终点、AI提前对准及恢复点随新线同步。
- 逻辑检查点仍顺序经过S1的CP12—14后合流，CP15在主线62.5%，不允许中途切入分支刷点。

## 已确认的问题二：生成器错误地只避让主线，S2穿过15m建筑

浏览器对现有城市合批网格逐个高架采样点进行艇身高度射线扫描，复现 **S2自身14%—16%**坡段穿过一栋建筑：世界位置约`x=761,z=−535`，此处水道高约+4.4至+6.1m。区域建筑中心约`(764.25,−546.36)`，是`CityDistricts`中`zone=4,j=0`的35×15×24m主体及上部结构。

具体原因：建筑候选来自`track.point()`，返回值带`route:null`；生成器调用`track.contains(p,-15)`，而`contains/project`遵循该显式路线字段，只检查主线，**没有检查近旁S2**。该建筑中心距S2中心仅约11.17m，仍被生成。仅清除路线字段也不足以成为长期修复：目前仍只检查中心与固定余量，未检查旋转后的完整建筑占地和三维通行范围。

浏览器已复现[被建筑吞没的驾驶画面](current-obstacle.png)和[外部定位画面](current-obstacle-context.png)。场景建筑是视觉网格，当前实体求解主要处理艇与艇、水道边界；这不是一个新建筑刚体参数错误，也不能用“关掉建筑碰撞”解决。

本条请求未重新附两张用户截图，因此不能断言与截图是同一栋；以上是本机当前代码和浏览器实际复现的一处明确冲突。

### 计划中的三维净空修复

1. 建筑布置检查必须显式检查主线、S1、S2所有路线，不能继承候选点的`route`选择。
2. 用旋转后占地/包围体对赛道扫掠通行体检测，不只检查建筑中心。普通路段保留艇宽、侧向余量和约6m上方驾驶净空；跳跃区还要检查50—60m/s实际飞行包络及余量。
3. 这栋建筑从S2扫掠空间外移，保持原有资产质量和数量；若与主线或相邻建筑冲突则重新选址，不裁掉一半建筑、不关闭碰撞掩盖穿模。
4. 同步约束桥墩、横梁、门架、隧道顶板与其他支撑；高处桥梁只要有足够净空可以保留，不因二维重叠就全部删除。

当前扫描覆盖`CityDistricts`中主线和两分支所有高度大于0.5m采样点、三个横向车道位置，发现9个艇身位置被同一实体占据，集中在上述S2段。[原始扫描](obstacle-scan.json)。它不是全场景的完整净空证明：尚需在实施阶段纳入GLB、实例化设施、艇身尺寸、头顶空间与完整飞行包络。

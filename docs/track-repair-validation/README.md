## S1出口改造及驾驶结果

旧问题是出口前局部约160°回折，而非最终约13°夹角本身。移除Catmull-Rom曲线后的正弦侧移，采用端点切向约束曲线，末段以五次权重平滑贴合实际主线。入口仍为48%，出口延后至61%；长481.6m。尾段从全宽14m逐步放宽至约24m，主线汇流区局部约40m宽，边界和隧道结构随新线调整。

最终方向差约0.16°。离散几何估算最小半径约66.5m，与初始规划候选的77m不同，**验收依据是实际驾驶结果，不以该半径推断手感合格**。

|接近工况|真实玩家模型输入回放|生产构建浏览器游戏循环|
|---|---|---|
|120km/h|零护栏接触，最低119.92km/h，完成汇流|零护栏接触，驶出后120.14km/h|
|140km/h|零护栏接触，最低139.92km/h，完成汇流|零护栏接触，驶出后140.26km/h|
|160km/h|零护栏接触，最低159.91km/h，完成汇流|零护栏接触，驶出后160.22km/h|

测试只写入起始位置，之后由现有油门/刹车/转向输入驱动，没有逐帧设置艇的位置或修改驾驶参数。216测试从较早的分支38%位置开始制动，**不代表216km/h可以不减速硬转**。自动回放能验证物理可驾驶性，不能替代用户手操体验验收。

玩家、分支AI和主线AI共同合流的实体碰撞测试通过，无持续重叠或死锁。浏览器还进行玩家+4AI混合汇流，五艇均离开S1；延伸行驶到S2窄入口时出现短暂碰撞排队，续跑后全部恢复前进。原始快照含低速时刻，没有将其隐藏成“全程不停顿”。见[浏览器基本结果](browser-results.json)、[氮气与拥挤续跑](browser-extra.json)、[驾驶与比赛记录](driving-results.json)。

## 建筑阻挡根因与完整净空修复

`CityDistricts`的建筑候选由`track.point()`生成，携带`route:null`。旧`contains(p,-15)`因此只检查主线，漏查S2；一栋35×15×24m建筑位于S2自身14%—16%的+4.4至+6.1m坡段，导致艇和摄像机进入灰色网格。不是通过关闭碰撞解决。

新增共享`TrackClearance`，按空间网格缓存三维扫掠通行体，检查旋转后的完整建筑包围体，查询不继承候选点的路线字段。覆盖主线、S1、S2、坡面、高架、六个传统跳台、四个自然离水点及落地后的45m缓冲；飞行包络按25/40/50/60m/s、现有重力和各跳跃参数生成。它是有限速度/路线假设下的保守包络，不是任意失控轨迹的数学证明。

当前生成2509个通行体：地面1277、飞行779、落水缓冲453。建筑候选冲突时外移到完整净空之外；自有桥梁、顶板、门架调整上方净空，桥墩保持接地；下层通道内的高架支撑避让。精细模块布置也接入同一检查接口，供未来扩充复用。

实际审计：

- 区域建筑 **59→59**、精细街区模块 **195→195**，没有减少建筑数量或精度。
- 14栋区域建筑因主线/分支/飞行包络净空风险而移位，包含原S2阻挡建筑，未用禁用碰撞掩盖穿模。
- 原高架艇身位置扫描侵入点 **9→0**；原始位置/驾驶相机对照图见截图集。
- 全部区域建筑和195个精细模块的包围体检查冲突为0；真实玩家飞行轨迹抽取的81个空中点，对区域合批建筑网格射线检查侵入为0。
- 既有GLB资产净空与PBR/LOD测试仍通过。没有声称逐三角形穷尽全场景、所有偏航与超速轨迹；未来新资产仍须给出正确包围体并接入此检查。

**N1是低速短跳**：120km/h回放和AI通过；用未减速的140–180km/h从前方弯道硬冲的早期探索会偏离窄跳台，未把这类失败算作通过。不改全局转向或让靠近即强制起飞。B区120/140km/h保持贴坡，160/180km/h离水，属于预期速度门槛；B的滞空较短，受测AI选择不做特技。A、C、S2和中型台具备完整特技窗口并成功奖励，没有为了凑数量放宽奖励规则。

### A/B/C与S2完整轨迹

- A：30%起坡，0→12→16m；120–180km/h实际落点在主线36.68%–37.48%，216km/h约38.02%，在40%旧桥之前完成接水。
- B：69%起坡，0→8→0m连续凸面；160–180km/h实际落点约73.79%–73.89%。低速自然贴坡，不添加人工触发器强制弹射。
- C：78.5%起坡，0→6→10m；120–180km/h实际落点82.78%–83.54%，216km/h约84.08%，均在预留82.5%–84.9%的宽港湾接水区内。
- S2：先以合理低速进入独立窄入口，随前方曲率控制速度，再加速爬至14m；120–180及216km/h均验证离水、实际落地、特技奖励。仍真正飞越0m主线，不把上坡当作空中，也不在空中重置Y。

碰撞体尺寸、同层水平响应和高度差过滤保留；新高度通过现有世界高度输入碰撞、摄像机、水花和音频。未添加计时回水、位置吸附或忽略空中碰撞。

## 比赛与AI验证

完整集成模拟使用当前玩家驾驶模型、4名AI、实体碰撞、固定60Hz物理、氮气及特技，玩家第二圈走S1、第三圈走S2。五位选手均完成 **72个顺序检查点/三圈**，完赛时间依次为316.05、322.00、343.38、347.28、345.32秒；按真实完赛时间排序，不按数组顺序。模拟包含511次接触步骤，能量均在0–100范围，未发生非法高度或永久卡死。

测试为证明所有AI能跑完，将最终结算调用延迟至五艇均完成；正常游戏仍保持玩家完赛时结算的原流程。没有声称人工在浏览器连续驾驶五艇三圈。

24个顺序门和合法入口激活规则保持，S1仍经过分支CP12—14后汇回主线；不会因捷径缩短距离跳过检查点刷圈。V3使用独立成绩键，V2记录保留，避免赛道改造后混用成绩。

生产浏览器验证覆盖S1各速度/氮气、混合汇流、全部新增点与A/B/S2实际腾空、AI通过C区、正式入口键盘加速/刹车与重开。正式入口41个模型/贴图请求成功，重开恢复40%氮气，未暴露私有测试钩子。

## 性能与质量保护

对同硬件RTX4060 Laptop、Edge无头、1600×1000、DPR1的生产编译版本进行短时对照；60帧预热后采180个真实RAF帧，场景使用相同固定模拟时间戳。GPU值来自18个可用且未disjoint的计时查询；CPU为提交/渲染函数耗时，不等同于纯逻辑耗时。

新增跳台按材质合批，保留全部几何、材质和可见细节。增加C区水槽沿用现有水面材质/镜面目标，没有额外重渲染整座城市。净空检查仅在初始化运行，不在每帧执行。

这组短时控制场景**未见明显性能下降**，不是全图/长时稳定60FPS保证；五艇场景仍约56FPS，1% Low偏低，原高精度多艇渲染成本仍存在。不能将此归结为本轮已经全面解决卡顿。

## 尚需用户验收与限制

1. 测试为自动控制输入驱动的真实游戏物理/浏览器循环，另有真实键盘烟测；没有人工手操体验结论。请重点确认S1在140–160km/h时的转向余量和视觉导向。
2. N1需在前弯减速对准，B区为速度相关短跳；并非每个点都保证任意线路、任意速度能做完整空翻。
3. 五艇挤在S2窄入口时仍可能明显减速排队；受测续跑恢复，无永久死锁。没有重写AI全局避让或取消正常碰撞减速。
4. 净空基于完整旋转包围体、指定速度包络及抽样网格验证；未穷尽所有偏航/极端碰撞后的路线。未来资产必须提供正确边界并接入公共检查。
5. 上层水面继续共享原有平面镜面近似，没有新增逐水层精确反射；本轮没有真实手机长时测试。

# 首次加载传输修复（2026-11-26）

## 原因与修改

标准画质冷启动实际模型/贴图响应体：电脑 134,835,723 字节，触控配置 31,220,653 字节。旧下载器在同一文件内逐片等待，每片最多从 256 KiB 起步，只有请求在 100 ms 内完成才扩大。高延迟网络难以达到这一条件，因而产生大量串行 Range 往返。此前增加重试和缓存没有解决首次传输的这一瓶颈。

本次构建将常用模型、KTX2 和手机 WebP 预切为最多 512 KiB 的普通静态 GET 文件。每个资源最多两个请求，资源队列仍最多三个，即最多六个响应体并行。无需先请求 HEAD 或 Range；每片及整文件都验证 SHA256，再交给原来的解码器。失败只重试对应分片，仍可回退至原文件。旧版完整缓存继续复用，包括服务器已通过 HTTP gzip 解压的缓存内容。

89 个资源、349 个静态分片已逐片及整体校验，重组后的 154,460,820 字节与现有原件完全一致。分片仅在构建输出中产生，不向 Git 重复提交二进制。原始资源保留，资源版本仍为 `88c9388eafb9...`。发布文件增大约 154 MB，单台设备所需下载量没有因此增加。

没有修改模型、贴图像素、分辨率、水面着色、反射、阴影、赛道、物理、AI、计圈或多人协议。增加了启动阶段的内部计时，用于区分传输、反射、阴影、编译和首帧耗时；没有将这些内容放进游戏操作界面。

## 验证与测量边界

- 271 项 Node 测试、13 项 Workers 测试、类型检查、生产构建通过。
- 缺失城市分片及损坏贴图分片：原文件回退后完整进入标准画质，驾驶及回首页通过。
- 旧完整缓存、旧 HTTP 解压缓存、分片中断续传、错序完成、版本变化及损坏缓存校验通过。二次进入没有模型/贴图网络请求。
- 两个实际浏览器、触控配置及本机大厅：房主/准备、慢玩家加载屏障、同步五秒倒计时、状态广播、断线恢复、连续一分钟及退出通过。
- 在同一份 28,635,328 字节快艇文件、每次响应固定延迟 250 ms、不限响应体带宽的原生浏览器传输测试中，旧方式 28.846 秒（110 请求、并发 1），新方式 7.397 秒（55 请求、并发 2）。两者完整 SHA256 相同。这是传输往返开销测试，不是整个游戏四倍提速或公网网速承诺。
- 完整游戏的固定延迟测试：旧版电脑 41.142 秒、触控配置 17.699 秒；第一候选电脑 25.054 秒；最终扩展至小贴图的版本电脑 40.575 秒、触控配置 22.018 秒。后一次初始化/首帧等 CPU/GPU 阶段也明显变慢，不能据此宣称最终版本完整启动稳定提升 39%。原始结果保存于本机 `work/startup-repair/`，后续需以公网实际加载验证补充。
- 早期测量脚本曾在成功加载后多等已消失的提示框 30 秒，该测量错误已纠正，早期错误总耗时不作为验收数据。阶段细分也证实该额外等待不是游戏反射生成耗时。

完整资源仍较大，网络吞吐量的下限依然存在；本次不通过降低画质缩减下载量。未在真实手机或中国大陆无代理网络上验证，因此不声称所有网络的首次加载均在某个秒数内完成。Render 与 Cloudflare 服务、配置及费用未变。

发布后须同时确认 Pages 成功、公开入口/Game 模块与本机构建一致、静态分片可取，并用默认浏览器协议实际启动公开游戏；仅上传成功不代表线上已生效。

# 第二捷径 CP19 计圈阻塞修复

用户反馈线上版卡在 `CP 19 / 23`，圈数始终为第一圈。实际浏览器通过驾驶输入复现：合法进入 S2 高架捷径，在飞跃时向左修正方向，距捷径中心线超过 10 米后临时路径标记被清除。落水回到同一捷径时已超过入口识别窗口，旧逻辑不再允许恢复捷径身份；即使实际穿过捷径 CP19、CP20，顺序计分也停在 18。

本次修复为每名选手保存本圈已合法进入过的捷径。临时偏离后，只有真正回到该捷径、顺向移动且高度正确，才能恢复身份。没有进入过的捷径仍必须从入口识别；不绕过检查点、不放宽门宽或高度、不允许瞬移计分。记录在本圈结束时清除，新比赛不继承，返回赛道操作不抹掉本圈合法入口记录。

验证证据：

- `before.json` / `after.json` 的 `flight-left` 是同一实际 Game.frame 驾驶轨迹。修复前到出口仍停在 18；修复后在回到水道时恢复 `harbor-cut`，正常通过 CP19、CP20。左右贴岸探测中未实际通过相应检查点的轨迹不作为通过案例。
- `three-laps.json`：正常发车开始，三圈均走 S2，三次故意在飞跃时向左偏移，三次触发临时路径丢失和恢复；无 AI routeIntent、无位置瞬移、无检查点注入。顺序通过全部 72 点和每圈 CP19（19、43、67），340.17 游戏秒完成三圈，显示五人结算；再赛一场重置成功。
- `three-laps.jpg` 为该次完整三圈的结算画面。
- 180 项测试通过，包含入口历史、临时偏离、CP19/20、逆向、瞬移、未进入捷径、每圈清除、选手隔离和重新比赛；TypeScript 和生产构建通过。
- 原有主路中央、内外侧和两条捷径路线也重新测试；玩家测试全部禁用 AI routeIntent。

加速功能测试期间仅跳过 GPU 绘制，截图时恢复；功能测试的执行耗时不用于声称帧率。游戏渲染、模型、材质、水面、阴影、画质设置、驾驶和碰撞参数均未改动。

独立完整渲染 A/B/B/A 对照见 `performance.json`：同一 Edge、1600×1000、DPR1、标准画质，每次预热 60 帧后测量 240 帧。城市五艇均值 36.473 → 36.592 FPS，S2 五艇 34.749 → 34.927 FPS，属于相近表现；两场景的绘制调用与三角形数量均完全一致，没有明显帧率回退。

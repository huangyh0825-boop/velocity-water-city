# 极速水城：不降画质性能优化验收

日期：2026-10-17。范围限于渲染实现和验证工具，没有部署。基线检查点为 Git 标签 `performance-baseline`（`8fc9413`），优化源代码提交为 `ac0a47f`。

本轮已完成性能分析、针对性优化、两组生产构建回放、真实时间循环测试、画面对照及功能回归。**正常和高速驾驶获得提升，五艇同屏仍未稳定达到60FPS**，不能宣称已消除所有卡顿。

## 测试条件与边界

同一设备：Ryzen 9 7945HX、约16GB内存、NVIDIA RTX 4060 Laptop GPU；Edge `155.0.4283.45`，ANGLE D3D11，WebGL2。浏览器自动化使用真实GPU的headless Edge，不是软件光栅化。

全部基准使用生产优化构建、1600×1000视口、DPR 1、标准画质；相同贴图、光照、水面相位和确定性输入。DPR 1是两版共同的测试设备条件，**没有修改游戏内部像素比、抗锯齿或渲染分辨率策略**。本机其他窗口尺寸、屏幕缩放或前台浏览器的结果会不同。

主对照每场景预热180帧，重置同一状态后采样180帧，每个渲染样本推进一个60Hz物理步。它用于比较相同模拟轨迹的渲染负载，**不是玩家完整一圈的实时平均帧率**。均值来自RAF间隔；1% Low按最慢1%间隔的均值换算，179个有效间隔中仅取最慢2帧，因此波动明显。

GPU使用 `EXT_disjoint_timer_query_webgl2`，另跑相同回放，每30帧采样一次，每场景6个有效样本。主FPS测试不插入GPU计时查询。反射递归渲染会暂停、恢复父查询，避免嵌套查询。GPU数值是相应绘制区间，不包含全部目标清理、上传、浏览器合成及显示延迟，不能当作精确的整帧端到端GPU时间。连续逐帧查询明显扰动了性能，因此未采用早期逐帧查询的FPS。

基准没有通过键盘解锁音频；真实键盘回归另外验证了音频运行。本报告的FPS不是“全部声音播放时整场比赛”的保证。两版测试顺序为基线→优化版→延长基线→延长优化版，没有在FPS测试期间并行跑构建或测试。

## 实际瓶颈

1. **多艇同屏主要受GPU绘制负载约束。** 每艘艇及车手包含4,927,792个三角形（含视觉附属件），五艘保持同质量。主画面、当前帧水面反射、局部自阴影重复处理这些网格。五艇场景所有Pass合计约7,599万三角形/帧；单艇主视角约1,601万。基线五艇GPU诊断均值：主画面区间10.95ms、反射8.98ms、局部阴影4.84ms、水面1.39ms。这里水面不是唯一或最大的成本。
2. **水面尾浪存在大量数学结果为零的片元工作。** 32个尾浪样本逐像素执行指数、噪声和三角计算，即使当前片元已在尾浪纵向有效范围之外。
3. **局部阴影存在CPU重复场景遍历与渲染状态切换。** 每艘艇原先用整个城市场景渲染仅属于自身的深度层，重复遍历无关建筑，且在同一Scene的无光深度Pass与有光主Pass之间切换程序参数。Three内部程序选择和Uniform提交出现在CDP采样热点中。
4. **相同ORM贴图通道被分别采样。** 某些车手/艇身材质将同一Texture同时用作AO、粗糙度和金属度，重复UV转换和采样可复用。
5. **未发现AI或物理是主要热点。** 主回放五艇AI总提交段均值约0.41ms、碰撞约0.13ms，水面CPU更新约0.018ms。CPU段使用 `performance.now()` 包裹，可能包含WebGL驱动等待，不能解释为纯CPU指令时间。

[CDP CPU诊断](performance-review/cpu-diagnostic-before.json)、[CPU采样原文件](performance-review/cpu-profile-before.json)、[分配采样](performance-review/heap-profile-before.json)来自前期独立诊断，用于定位，不能直接作为最终前后性能差值。采样期间有GC，但没有足够证据认定持续内存泄漏或GC是当前主要帧率瓶颈。

## 采用的优化

|文件|修改与保留条件|
|---|---|
|`src/player/HeroLighting.ts`|缓存当前视觉资产的深度投射网格和材质；只渲染相同快艇根节点，不再遍历整个城市场景；异常时仍恢复全部材质与渲染状态。保留2048²深度图、全部投射网格、相同光向、偏移及原9次PCF采样。|
|`src/player/Watercraft.ts`|视觉资产重载后增加版本号，使阴影缓存正确失效；没有修改模型、骑姿或物理。|
|`src/player/PackedMaterialSampling.ts`（新增）|仅当AO/金属度贴图与粗糙度贴图是同一Texture时复用采样及UV；不同贴图保留Three原着色流程；组合Shader缓存键避免变体混用。|
|`src/player/RacerMaterials.ts`|为现有玩家及AI材质克隆接入相同的ORM采样复用，不修改材质数值和纹理。|
|`src/effects/Water.ts`|尾浪的纵向gate或强度严格等于零时跳过无贡献运算；保留全部波浪、32个尾浪样本、反射及采样；复用尾浪排序数组，顺序与原filter/sort一致。|
|`tests/performance-rendering.test.ts`（新增）|验证ORM共享条件和缓存键、阴影根节点与异常恢复/重载、尾浪顺序和样本完全一致。|

没有重新创建材质/几何体/纹理的水面每帧路径；水花原本已使用对象池及单个Points绘制，模型资源也已缓存共享，未重复改造这些已有机制。建筑布局、密度、LOD距离和剔除策略没有修改。

网格索引重排、四比较PCF重写、额外艇身深度预Pass均做过探索。索引重排没有稳定收益，PCF重写没有可靠收益，额外深度Pass反而明显拖慢多艇场景，**全部撤销，没有进入最终版本**。不以早期不同热状态的巨大表面提升作为结果。

## 主对照结果

以下为完整八场景同条件第一组结果。帧时间越低越好。所有场景优化前后超过50ms/100ms的间隔均为0；这说明该短测试未出现明显长卡顿，**不能宣称减少了原本就未观测到的长卡顿**。

|场景|平均FPS 前→后|平均帧时间ms 前→后|1% Low FPS 前→后|
|---|---:|---:|---:|
|城市静止|161.5 → 161.5|6.19 → 6.19|119.0 → 95.2|
|正常驾驶|135.9 → 156.2|7.36 → 6.40|53.3 → 117.6|
|高速驾驶（结束180km/h）|140.0 → 159.7|7.15 → 6.26|80.3 → 117.6|
|五艇同屏|40.5 → 42.0|24.67 → 23.81|32.0 → 34.2|
|氮气（结束216km/h）|137.2 → 158.5|7.29 → 6.31|60.1 → 117.6|
|跳跃/特技/落水回放|162.7 → 189.3|6.15 → 5.28|119.0 → 79.7|
|密集建筑区|162.7 → 161.5|6.15 → 6.19|117.6 → 119.0|
|碰撞水花场景|46.1 → 48.3|21.69 → 20.72|31.9 → 34.4|

静止及跳跃的1% Low没有改善，密集区均值也有小幅回退；没有挑掉这些结果。样本较短，不能把个别极值的变化全部归因于优化。正常/高速/氮气的平均提升约14%–16%，五艇同屏约3.6%，碰撞约4.7%。

关键工作量前后相同：

|场景|Draw Calls均值 前=后|全部Pass三角形均值 前=后|水面GPU区间ms 前→后|局部阴影CPU提交段ms 前→后|
|---|---:|---:|---:|---:|
|高速|340.92|16,014,072|1.332 → 0.459|0.282 → 0.186|
|五艇|793.14|75,993,444|1.394 → 0.603|1.185 → 0.718|
|碰撞|713.61|65,400,321|1.381 → 0.529|1.081 → 0.639|

这里没有把合批减少Draw Calls作为成果：实际没有减少。水面GPU区间约下降57%–66%，局部阴影CPU提交段下降约34%–41%；模型及反射的GPU负担仍然存在。所有场景GPU几何体/纹理计数、模拟结束状态也逐项断言一致。**纹理对象计数不等于显存字节数**，当前环境没有可靠的总VRAM实占测量，未虚报显存节省。

## 未解决的限制

1. 五艘高精度资产及其反射/阴影的GPU成本仍高，密集同屏约42FPS。本轮保留全部几何和效果，没有以画质换取稳定60FPS。
2. 首次资产上传/Shader编译仍可能产生明显停顿。独立冷启动基线诊断中，首个绘制约7.46秒，首次蒙皮包围球计算累计约336ms；这是冷启动诊断，不是暖机后稳态FPS，也没有证据将整段时间全归因于蒙皮。[原始诊断](performance-review/cold-bounds-before.json)。本轮未改动蒙皮边界或加载流程以冒险掩盖它。
3. 静止场景和个别1% Low没有收益；短采样无法保证用户所有游玩位置都更快。建议重点试玩起跑多艇聚集、镜面反射明显的建筑区、碰撞水花和落地瞬间。
4. GPU计时与浏览器驱动/功耗状态仍有波动，没有可靠总显存测量；没有宣称达到硬件极限，后续更深的渲染批处理需要单独验证。

## 复测方法与工具

不需要重新安装依赖或重新生成模型。Windows本机有Node，npm不可直接调用时可使用现有pnpm运行npm，或直接运行下面的包内命令。

```powershell
node node_modules/typescript/bin/tsc --noEmit
node node_modules/tsx/dist/cli.mjs --test tests/*.test.ts
node node_modules/vite/bin/vite.js build

# 同一工作区用Git源代码覆盖构建基线，不切换/覆盖工作文件。

$env:PERF_OUT_DIR='.qa/perf-build'
node scripts/qa/build-performance.mjs
Remove-Item Env:PERF_REV
$env:PERF_OUT_DIR='.qa/perf-after'
node scripts/qa/build-performance.mjs

# 分别在两个终端启动，仅本机预览。

node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 5176 --strictPort --outDir .qa/perf-after

# PLAYWRIGHT_MODULE设置为本机Playwright包路径；若项目环境已能解析则可省略。

```

# 四位房间大厅 · 第一阶段

同样的四位号码进入同一真实服务中的同一房间。当前提供最多五名玩家、准备/取消准备、改名、离开、房主转移、刷新重入和断线重连。当前阶段不启动联网竞速。

本机与同一局域网：在项目根目录运行 `node scripts/dev-with-lobby.mjs`。它会启动大厅 8787 和游戏开发预览 5185。浏览器打开 `http://127.0.0.1:5185/`；其他设备打开终端显示的 Network 地址，输入相同房间号即可会合。Windows 防火墙如阻止局域网入站，需要允许相应端口。

生产构建预览：大厅运行时执行 `node node_modules/vite/bin/vite.js preview --host 0.0.0.0 --port 5183`。Vite 将 `/api/lobby` 请求代理到本机 8787。应先执行生产构建。

公网部署：

1. GitHub Pages 托管前端，不能运行常驻大厅进程。大厅需部署到一个可运行 Node.js 的服务，并通过 HTTPS 提供访问。
2. `npm run build:lobby` 会生成 `dist-lobby/lobby.mjs`。该单文件启动时仅依赖 Node.js 22+，不依赖开发包、Three.js 或模型资源。执行 `node dist-lobby/lobby.mjs`，默认监听 `0.0.0.0:8787`，可用 `LOBBY_PORT` 修改。
3. 服务端环境变量 `LOBBY_ALLOWED_ORIGINS` 填写允许访问的完整前端来源，例如 `https://huangyh0825-boop.github.io`。多个来源用英文逗号分隔。HTTPS 可由部署服务或反向代理提供。
4. 前端 `.env.production.local` 填写 `VITE_LOBBY_URL=https://你的大厅域名/api/lobby` 后重新构建部署。这个地址是公开连接地址，不要在 `VITE_` 变量中放服务器秘密。
5. 部署后用两个独立设备实测同号入房、准备和离房，再确认公网大厅上线。当前本机验收不代表已经部署公网大厅。

协议使用小型 JSON 请求，约一秒同步一次大厅状态；进入训练后会离开房间并停止大厅轮询。后续竞速可以单独接入 WebSocket 传输与服务器比赛会话，不将大厅轮询用于赛车同步。

设备固定标识、私有重入凭据、可改游戏 ID、训练设置、统计和最近 30 次记录保存在浏览器本地。ID 改名不更换设备标识，也不清空记录。当前不是跨设备账户系统；更换浏览器或清除网站数据会建立新档案。对手只能读取公开游戏 ID 和准备状态，不能读取其他设备的标识或重入凭据。

房间保存在大厅进程内存中，空房自动清理；失联成员约 30 秒后移除。大厅重启不影响各设备本地训练记录。房间号保持四位字符串，因此 `0042` 和 `0043` 是不同房间。
